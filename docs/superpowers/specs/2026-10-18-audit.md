## 2. Code

### Structure

- **Projects (8)** and their tags: `dashboard` (`type:app`, `scope:dashboard`), `landing`
  (`type:app`, `scope:landing`), `dashboard-e2e` (**none**, F11), `ui`, `tokens`, `mock-api`
  (`type:lib`, `scope:shared`), `shared-kernel` (`type:lib`, `scope:shared`, `layer:domain`),
  `booking-domain` (`type:lib`, `scope:booking`, `layer:domain`).
- **Graph** (`npx nx graph --file=graph.json`): `dashboard → ui, tokens, mock-api`;
  `landing → tokens, ui`; `ui → tokens`; `booking-domain → shared-kernel`;
  `dashboard-e2e → dashboard` (implicit). No cycle, no boundary violation (`npm run lint` passes),
  and `check:architecture` agrees: 8 containers, 8 dependencies.
- **Size.** Non-spec TypeScript: dashboard 33 files, 3,593 lines; ui 20, 1,795; landing 20, 996;
  booking-domain 8, 542; tokens 4, 217; shared-kernel 6, 177; mock-api 4, 125. Nothing is too large
  to hold in one session. `mock-api` is small but is a real seam (the interceptor that the
  production build replaces, ADR 0006), so merging it is not proposed.
- **Target structure.** The Nx library types (feature, ui, data-access, util) already apply
  inside bounded contexts through `layer:` tags (ADR 0021). The dashboard's pages, data and mock
  live in the app, which is what Nx recommends until a second consumer appears; extracting them
  now would add libraries with one caller each. No structural refactor is proposed beyond F11.
